## Implementation decisions

These resolve details the contract leaves open, beyond the interpretations in [section 13 of the contract](o3-closeout-contract.md); each is reversible.

1. **Legacy v1 spellings kept; v2 strict.** *(Corrected; the candidate required integers for both formats.)* A v1 `schema_version` may be any non-boolean JSON number equal to 1 (`1`, `1.0`, `1e0`), as before O3, and is normalized to the integer 1. A v2 `schema_version` must be the integer `2`; `2.0` and `2e0` are refused. Booleans, strings, null and other numbers are refused for both.
2. **Replay never needs the live package to be eligible.** A saved operation id is recognized, and compared, before any gate, so a replay works for a package that has since drifted, lost evidence, been left over-reserve or become incomplete.
3. **Count-only deficit.** *(Corrected; the earlier wording confused total and active acceptances.)* The records counted against the ceiling are `A + W + U`, which is `2A` because `U = A - W`, so the count invariant is violated by `A >= 51` acceptances in total, withdrawn or not, while the file itself holds only `A + W` records, which the parser limits to 100. A withdrawal cannot reduce it: it adds a record and removes a reserved slot, so `2A` is unchanged. A package with `A = 51`, `W = 40` and `U = 11` has 91 records, is byte-compliant and short only by count, so it accepts no recovery withdrawal; it cannot be built with the tool (the eleventh active acceptance would exceed `2A <= 100`), only by a hand edit. The tests build it from real operations plus one hand-edited record, parse it, assert those figures, and show that `plan_withdrawal`, the store and the command each refuse a withdrawal and leave the original bytes unchanged.
4. **Ordinary writers refuse any deficient result.** Even a write that shrinks a deficient package is refused unless it is a deficit-reducing withdrawal.
5. **Delivery commands have no JSON output.** The contract asks for no new query or preview subsystem; `show --json` is the machine-readable view.
6. **`omnitient schema` defaults to v1** so existing callers see the same bytes.
7. **The placeholder-objective rule is shared.** `delivery.py` imports the pattern from `readiness.py` rather than copying it, and does not call `readiness.evaluate`, so acceptance evaluates no readiness.
8. **Test helpers are shared between test modules** by importing the first-defined module (for example `test_delivery.padded`), because the repository's naming hook allows only `test_*.py` files and `conftest.py` in `tests/`.

## Review-fix round

Two reviews of the correction candidate (407f9ca) were done: a regular-Claude review (no blocking findings in its scope) and a Codex structured and adversarial review (`changes_required`).
The controller's completion also failed, among other reasons for want of trusted external CI.
This round fixes the concrete defects and test gaps they found; it does not change those verdicts, run any review again or supply CI, and it makes no claim of independent approval.
The finding ledger and the evidence for this round are kept outside the repository, with the test and hook logs.

**Fixes.**

- **Recovery is a withdrawal and nothing else (Codex F-001).** `delivery.check_reserve` with `recovery=True` first requires exactly one appended withdrawal, of an acceptance that is not yet withdrawn, with the earlier history and every other field of the package unchanged, before any reserve rule applies and whether or not the result is compliant (the compliant result no longer skips the rule). Refusals use `store.recovery` and write nothing.
- **Complete delivery of the report (Codex F-003).** `_report` requires the text stream's write count to equal the length of the document in characters; a short count, zero, `None` or a larger count is an output failure, never retried and never rolled back.
- **Operation-aware guidance (Regular F1, Codex F-004).** An output failure after a saved acceptance or withdrawal still points at a same-operation-id replay. After a saved upgrade it says that the upgrade is saved, that an upgrade has no operation id and no replay, that the same `--apply` command is refused by design, and to inspect with `show` or the preview. A replay, a preview and a no-op say that this run wrote nothing.
- **Best-effort notes (Codex N-1).** The optional stderr notes after persistence, and the failure message itself, cannot raise. If stderr is unusable the receipt still goes to a working stdout, and if both are unusable the exit status is the only signal and nothing claims a delivery.
- **Reserve timestamp (Codex F-002).**
  The worst-case withdrawal used the 20-byte ASCII timestamp the tool writes, but the complete validation (the pattern plus `strptime`) admits spellings up to 44 bytes: four-byte decimal digits in the year and in the second digit of day, hour, minute and second, never in a month digit.
  An acceptance with a 32-character id followed by a maximal withdrawal with such a timestamp is accepted by the parser and grows the file by 17,456 bytes, which was 22 more than the old reserve of 17,434.
  The reserve now uses the widest spelling the pattern itself admits (14 four-byte digits, 62 bytes) so that it does not depend on the standard library's parser; it is 17,476.
  The manifest limit, the record limits and the capacity policy are unchanged, and v1 timestamp behaviour is untouched.
  The width probe gave the same 44-byte result on Python 3.12, 3.13, 3.14 and 3.15 (a stdlib-only probe of the validation, not a test run on those interpreters).
